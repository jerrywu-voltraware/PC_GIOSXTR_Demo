# 錯誤通知彈窗開關 設計規格（2026-11-12）

## 目的

使用者要可以選擇「發生錯誤時是否彈出錯誤通知視窗」。預設彈出；關閉時錯誤仍要記錄，
並在固定位置提醒有未讀錯誤。背景：PTU 韌體負溫誤判過溫（例 `-12 / 10 (-12 > 10)`），
會反覆彈窗干擾（韌體不在此 repo，未修）。

## 行為

1. **設定**：QSettings key `notifications/errorPopup`（bool，預設 True）。
   - 設定對話框新增「通知」分頁：勾選框「發生錯誤時彈出錯誤通知視窗」＋說明文字
     「關閉後，錯誤仍會記錄在錯誤清單，並在右上角顯示未讀錯誤數提醒。」
   - 錯誤通知視窗（ErrorLogDialog）底部加勾選框「不要自動彈出（可在 設定 → 通知 重新開啟）」，
     與設定雙向同步（勾＝關閉彈窗）。
2. **彈窗開啟（預設）**：行為與現在完全相同（`append_error` 會 show + raise）。
3. **彈窗關閉**：
   - 錯誤仍 `append_error` 進清單，但不 show / raise。
   - 主視窗分頁列右上角（「設定」左側）顯示紅色提醒按鈕「⚠ N 筆錯誤」，tooltip 為最後一筆錯誤摘要；
     N = 自上次查看後的未讀錯誤數。N = 0 時隱藏。
   - 點提醒按鈕 → 開啟錯誤通知視窗（show + raise），未讀歸零、按鈕隱藏。
   - 錯誤視窗本來就開著（使用者自己開）時新錯誤進來，不增加未讀。
   - 清除清單 → 未讀歸零。
4. **從關閉改回開啟**：未讀提醒保留到使用者點開為止（不自動彈出舊錯誤）。

## 順便修正（Waveform）

- F6：`WaveformPage._update_shared_x_window` 的左界是 `max(0, right - history + 1)`，
  圖在裝置串流一段時間後才加入時，曲線只佔畫面右側（實機截圖約右 40%）。
  改為左界 = `max(right - history + 1, 所有選取 series 的最小 x)`，讓資料填滿可視範圍。
